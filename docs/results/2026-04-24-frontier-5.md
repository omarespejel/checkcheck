# Frontier-5

Date: 2026-04-24

This report asks the next immediate question after `frontier-4`.

The open hope was:

> maybe minimal `9`-byte DER is too rigid, but slightly longer non-minimal DER still gives enough overlap to beat the current QSB point.

That is the right next place to look because the byte penalty for short non-minimal DER is not very large. If overlap came back quickly, the frontier could still move.

The new tool for this step is `tools/der_surface_frontier.py`.

## Result 1: exact `10`-byte DER is still structurally dead

For exact payload length `10`, the pushed token prefix is:

`0a 30 07 ...`

To get any proper prefix/suffix overlap, some token would need an internal copy of at least the `3`-byte prefix `0a 30 07`.

But exact `10`-byte DER only allows integer-length splits `(1,2)` or `(2,1)`, so neither `r` nor `s` can contain a `3`-byte internal motif at all.

So exact `10`-byte DER is still structurally overlap-free in the same sense that minimal `9`-byte DER was structurally overlap-free.

The random probe agrees:

- `10,000` random `4`-token families
- ordered `2`-of-`4` deletion
- best unique ordered outcomes: `6`
- plain subset baseline: `6`
- best unordered-subset multiplicity: `1`

So the first non-minimal step does not open a new surface.

## Result 2: exact `11`- and `12`-byte DER do not obviously die on byte budget

This is important because it keeps the question honest.

Under the current QSB-like static choice budget, longer DER does reduce the number of hardcoded options `n`, but only gradually:

| Payload length | Per-choice static bytes | Max `n` under current budget | Signed `8+8` bits | Gap vs baseline |
|---|---:|---:|---:|---:|
| `9` | `31` | `150` | `84.51` | `0.00` |
| `10` | `32` | `145` | `83.71` | `0.80` |
| `11` | `33` | `140` | `82.88` | `1.63` |
| `12` | `34` | `136` | `82.20` | `2.32` |
| `13` | `35` | `132` | `81.49` | `3.03` |

So exact `11`- and `12`-byte DER are not obviously ruled out by cost alone.

If they created even a modest amount of new searched state, they could still matter.

That is why the next empirical result matters.

## Result 3: exact `11`- and `12`-byte DER stayed flat in random family search

The tool runs `10,000` random `4`-token family probes for exact payload lengths `11` and `12`.

For both surfaces:

- ordered `2`-of-`4` deletion
- best unique ordered outcomes: `6`
- plain subset baseline: `6`
- best unordered-subset multiplicity: `1`

So at this search depth, short non-minimal DER still does not exhibit usable overlap gain.

This matters because exact `11` and `12` are the first short lengths where internal prefix fragments can fit inside one integer field at all.

The byte budget said they had room to be interesting.

The overlap search said they still were not.

## Result 4: the obvious prefix-embedding motifs also stayed flat

Random search can miss rare structured families, so the tool also exhaustively checks two motif-heavy candidate pools:

1. `len11_motif_pool`
   built around exact `11`-byte signatures whose `s` field embeds the obvious `0b3008`-style prefix fragment.
2. `len12_motif_pool`
   built around exact `12`-byte signatures whose `s` field embeds the obvious `0c300902`-style prefix fragment.

Each pool has `8` candidates, and the tool exhaustively checks:

- every `4`-token family from the pool
- every script order for that family
- ordered `2`-of-`4` deletion

Result for both pools:

- best unique ordered outcomes: `6`
- plain subset baseline: `6`
- best unordered-subset multiplicity: `1`

So even the first obvious short-DER overlap motifs are not producing usable extra states.

## Result 5: short non-minimal DER now looks weak for a different reason than before

`frontier-4` ruled out minimal `9`-byte DER because the valid surface was structurally cross-bifix-free.

`frontier-5` adds a different kind of negative result:

- exact `10`-byte DER is still structurally dead
- exact `11`- and `12`-byte DER are not obviously too expensive
- but the first empirical searches on those surfaces still produce no gain

That is a stronger narrowing step than just saying “longer DER costs bytes.”

The problem is not just price.

The problem is that short DER-shaped blobs still look too rigid to create useful `FindAndDelete` expressivity.

## What is left

The next worthwhile step is no longer “try one more short DER tweak.”

The next worthwhile choices are narrower:

1. Higher-order overlap search on longer DER surfaces:
   larger family size, larger selection size, or more structured local search than ordered `2`-of-`4`.
2. A different valid selectable blob family entirely:
   stop treating signature-shaped DER blobs as the only natural surface.
3. A new verification surface:
   move away from overlap-style deletion as the main entropy lever.

That is where the repo should go next.

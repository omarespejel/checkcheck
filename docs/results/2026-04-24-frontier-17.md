# Frontier-17

Date: 2026-04-24

This report follows `frontier-16`.

`frontier-16` found a promising numeric result:

- asymmetric partial-polyglot beats Config A in the model at `143` trusted
  polyglot elements;
- it first crosses the public baseline collision level at `200` trusted
  elements;
- witness size stays roughly flat, so the numeric blocker is setup cost.

The next gate was not another setup search.

It was this:

> can the current modeled construction be trusted as script-feasible?

I added `tools/qsb_stack_sanity.py` for that gate.

## Result 2: the stack gate is a no-go

The new stack gate checks whether the modeled constants select the intended
stack items under the repo's documented witness layout.

Command:

```text
python3 tools/qsb_stack_sanity.py
```

Output:

```text
# stack-feasibility-gate

decision=NO-GO

checks:
- vendored-qsb-first-selection-roll: FAIL
  expected=idx0
  actual=H4
  detail=builder constant depth=2*n+1=11; documented witness puts idx0 at depth 12
- vendored-qsb-cms-key-nonce-roll: FAIL
  expected=key_nonce
  actual=selected_sig2
  detail=with <m> above key_nonce, OP_2 OP_ROLL moves the first selected signature, not key_nonce
- modeled-split-polyglot-first-selection-roll: FAIL
  expected=idx0
  actual=B205
  detail=model constant depth=m+q+1=271; documented witness puts idx0 at depth 272
```

The important part is not the small toy parameters. The important part is the
structural mismatch:

- the first QSB selection roll does not select the next witness index under the
  documented layout;
- the `OP_2 OP_ROLL` multisig setup does not move `key_nonce` when `<m>` has
  already been pushed above it;
- the asymmetric split-pool formula inherits the same kind of roll-position
  problem.

This does **not** prove QSB or Binohash cannot be made executable. Binohash has
public proof-of-concept transactions, and Appendix D of the Binohash paper
states the polyglot optimization as a valid direction.

It does prove a narrower but important point:

**the current repo result is still a budget frontier, not yet an executable
script construction.**

## Result 3: the right decision is no-go for more frontier tuning

Decision:

**NO-GO on continuing to optimize the asymmetric partial-polyglot curve until
the stack-correct script exists.**

Reason:

- The numeric result is interesting but not yet enough to claim feasibility.
- Trusted setup is already expensive, even at the improved `143` threshold.
- More search over `m/q/s/b` is low-value until the construction is tied to a
  concrete stack-correct script.

This changes the next task.

The next task is not:

- more DER motif hunting;
- more setup-cap sweeps;
- more symmetric vs asymmetric tuning.

The next task is:

1. import or write a regtest-proven QSB round script;
2. make the polyglot selection loop stack-correct inside that script;
3. rerun the asymmetric optimizer against the real emitted script bytes and
   roll constants.

Only after that should we decide whether the `143`-element threshold is a real
research result or just a model artifact.

## Bottom line

The current discovery is still interesting, but it is not yet "true enough" to
pitch as a follow-up construction.

The go/no-go answer is:

**NO-GO for publishing or extending the asymmetric polyglot economics right now.**

**GO only for the narrow implementation gate: executable stack-correct
polyglot QSB round first.**

# Frontier-22

Date: 2026-04-24

This report follows `frontier-21`.

`frontier-21` proved the corrected `258` point at the byte/interpreter level,
but only with signature checks stubbed. The next question was:

> can we now replace the stubs with real trusted-setup artifacts?

The answer is:

**not locally, and not cheaply enough to hide.**

## What the trusted setup must produce

For each polyglot commitment `P_i`, the setup needs a secret `x_i` such that:

```text
HASH160(x_i) = P_i
```

and the same `P_i` must be usable as an ECDSA signature byte string inside
`OP_CHECKMULTISIG`.

So each `P_i` must be a 20-byte HASH160 output that also parses as a valid
consensus-level DER ECDSA signature encoding.

That is the polyglot condition.

For the corrected `baseline_collision_sigop_corrected_258` target, the script
needs:

- round 1: `106` polyglot commitments;
- round 2: `152` polyglot commitments;
- total: `258` trusted polyglot commitments.

## Result 1: exact DER-20 probability matches the QSB target

The new tool:

```text
python3 tools/polyglot_trusted_setup_probe.py
```

computes the structural probability for a random 20-byte string to be accepted
as a consensus DER signature encoding under the same rules used by the vendored
QSB code.

Result:

```text
structural_probability_bits=46.4273
```

That matches the `~2^46.4` QSB search target.

For `258` required setup elements, the expected setup work is:

```text
expected_setup_hashes=2^54.41
approx_recoverable_setup_hashes=2^55.41
expected_setup_days_at_1GH=277.27d
expected_setup_days_at_10GH=27.73d
expected_setup_hours_at_1TH=6.65
```

So the setup is not magic. It is `258` independent DER hits. The
`approx_recoverable` line adds a rough extra bit for the fact that the DER
signature's `r` value also has to be a recoverable secp256k1 x-coordinate.

## Result 2: local full setup is a no-go

Short local runs on this machine landed in the low hundreds of thousands of
HASH160 trials per second. Even a faster sample run measured:

```text
hash160_per_second=712364
estimated_local_days_for_real_setup=389220.8
```

The exact rate moves between runs, but the conclusion does not.

Laptop/local CPU setup is not a credible path.

## Result 3: the toy setup path works

The same tool runs a toy setup with an easier predicate so we can check the
artifact shape without pretending the real setup completed.

Example non-deterministic run:

```text
toy_bits=16
requested_hits=4
trials=167878
expected_trials=262144
observed_over_expected=0.640
first_hit_commitment=0000802e642882a2eabb7ce168cce962cce51633
```

This validates the mechanics:

- generate a secret;
- compute `HASH160(secret)`;
- keep hits that satisfy the target predicate;
- record `(secret, commitment)` pairs for script/witness construction.

It does not validate the real cryptographic setup. It validates the generator
shape and the work model.

The corrected `181` point is the cheapest meaningful setup target, but it only
beats Config A. The corrected `258` point is the first baseline-collision
crossing. The `300` point is stronger, but setup is larger.

## Go/no-go

Decision:

**NO-GO for completing full cryptographic validation locally.**

**GO only if we are willing to run a GPU/distributed trusted setup.**

This is now the honest state:

- the script idea survives independent interpreter validation;
- the setup cost is real and dominates;
- the original QSB path avoids this extra trusted setup burden;
- our path buys script/collision-shape improvements at the price of a large
  precomputed polyglot commitment table.

## Recommendation

Do not keep tuning the frontier locally.

There are only two useful next actions:

1. If we want to continue this branch, build/export GPU setup artifacts for
   `configA_sigop_corrected_181` first, because it is the cheapest meaningful
   full-crypto target.
2. If we do not want to fund a distributed setup, stop the polyglot branch here
   and write it up as a bounded negative/conditional result.

## Bottom line

The discovery is real but conditional.

The corrected polyglot branch is not dead, but it is no longer a cheap
implementation win.

It is a trade:

**pay a trusted setup of roughly `2^54` HASH160 trials to recover a
non-standard, miner-direct, current-consensus script candidate.**

That may be interesting research, but it is not something this repo can finish
cryptographically on local CPU.

# Frontier-14

Date: 2026-04-24

This report follows `frontier-13`.

`frontier-13` pushed DER-shaped selectable blobs close to exhaustion:

- one-anchor DER stayed flat,
- two-anchor DER stayed flat,
- three-anchor DER stayed flat.

So the next high-ROI move was not another blob-geometry search.

It was the **polyglot digest** branch already noted in the upstream QSB paper:

- grind a preimage `P_i` such that `HASH160(P_i)` is a valid DER signature,
- use `HASH160(P_i)` as the hardcoded selectable element,
- use `P_i` as the revealed HORS preimage.

That merges the commitment and dummy signature into a single hardcoded element.

The new tool for this step is `tools/polyglot_frontier.py`.

This is a **budget model**, not a full script implementation. The script shape
is modeled directly from the upstream paper’s claim:

- save roughly `10` bytes per hardcoded pool entry,
- save `2` non-push opcodes per signed selection,
- keep the current puzzle and `CHECKMULTISIG` structure otherwise.

## Result 1: polyglot is the first branch that materially reopens the frontier

The first headline point keeps the public QSB pool size fixed at `n = 150`, but
uses all-signed `10 / 10` instead of the current `8 / 8` or bonus-key variants.

### Same-`n` polyglot point

- `n = 150`
- rounds: `10 + 0b`, `10 + 0b`
- ops: `201`
- bytes: `6953`
- signed digest bits: `100.11`
- subset search bits: `100.11`

Compare that to the current public references:

### Current QSB baseline

- bytes: `9953`
- ops: `197`
- signed digest bits: `84.51`
- subset bits: `84.51`

### Current QSB Config A

- bytes: `9967`
- ops: `201`
- signed digest bits: `80.35`
- subset bits: `92.47`

So the same-`n` polyglot point does three useful things at once:

1. removes bonus keys entirely;
2. clears the round target without mismatch (`50.05` bits per round);
3. beats the public QSB points on signed digest size by a large margin.

The deltas are concrete:

- `+15.59` signed bits vs. the public baseline;
- `+19.75` signed bits vs. Config A;
- about `3014` bytes less script than the current baseline.

That is the first genuinely positive frontier result in the repo after the DER
exhaustion work.

## Result 2: under the same limits, the max signed point is much stronger than current QSB

If the script budget is spent more aggressively, the modeled max signed point
under the current limits is:

- `n = 222`
- rounds: `10 + 0b`, `10 + 0b`
- ops: `201`
- bytes: `9977`
- signed digest bits: `111.71`
- subset bits: `111.71`

Under the same simple security model used throughout the repo, that implies:

- second pre-image bits: `158.11`
- collision bits: `102.26`

So polyglot does not just recover the baseline.

It materially moves the frontier outward.

## Result 3: polyglot shifts the bottleneck from script budget to trusted setup

The catch is operational, not combinatorial.

The tool models the one-time trusted setup cost as:

- `46.4 + log2(2n)` hashes

because two rounds need `2n` polyglot elements and each element is a DER-valid
`HASH160` grind.

That gives:

### Same-`n` polyglot point (`n = 150`)

- trusted setup bits: `54.63`

### Max signed point (`n = 222`)

- trusted setup bits: `55.19`

This lands in almost the same range as the paper’s cited one-time polyglot
grinding cost (`~2^53.5` hashes for the public-scale construction).

So the research picture changes in a useful way:

- DER-shaped blob geometry was the blocker for the earlier branches;
- for polyglot, the blocker is no longer script size or opcodes;
- it is the trusted secret grinding requirement.

That is a much more promising kind of blocker.

## Result 4: the practical frontier is now clearer

The tool also shows the best symmetric all-signed points under the current
limits:

- `t = 8`: `n = 224`, `93.95` signed bits
- `t = 9`: `n = 223`, `103.01` signed bits
- `t = 10`: `n = 222`, `111.71` signed bits

And the minimum `n` needed to clear the `46.4`-bit round target without bonus
keys:

- `t = 8`: `n = 214`
- `t = 9`: `n = 152`
- `t = 10`: `n = 118`

That last line is important.

Polyglot does not just make stronger high-end points possible.

It also makes it easy to build **smaller, all-signed, no-bonus** points that
already clear the round target.

## Result 5: this changes what the repo should do next

This is now the highest-signal conclusion in the repo:

**polyglot is the first branch that appears to genuinely beat the public QSB frontier under current Bitcoin limits.**

The next serious work should no longer be another DER-anchor experiment.

The best next steps are:

1. refine the polyglot model into a more explicit script/accounting model and
   confirm the exact byte formulas;
2. price the trusted setup more carefully:
   how many elements are actually needed, and what device class could grind
   them locally;
3. explore partial-polyglot variants that keep the byte savings while reducing
   trusted setup exposure.

At this point, the frontier has moved:

- from `FindAndDelete` geometry,
- to **polyglot setup economics**.

# Frontier-11

Date: 2026-04-24

This report follows `frontier-10`.

`frontier-10` left the repo with a sharper target:

> can we find a valid selectable blob family with explicit destructive conflict structure?

The natural first attempt is to take the expressive toy mechanism seriously and
try to lift it into valid DER directly, instead of doing another blind search.

The new tool for this step is `tools/der_conflict_lift_frontier.py`.

It studies a specific valid-DER family:

- exact-length DER payloads,
- one-byte `r`,
- `s` begins with the exact pushed-token anchor for that same length,
- the short distinguishing code is carried both in `r` and again inside `s`.

This is the cleanest straightforward valid-DER analogue of the toy conflict
gadget found in `frontier-9`.

## Result 1: the direct toy conflict lift already fails

The first probe lifts the exact toy conflict-only code order:

- `0101`
- `0102`
- `0303`
- `0203`

into exact-`15` coupled-anchor DER.

Result:

- unique ordered outcomes: `6`
- max results per unordered subset: `1`
- unordered subset baseline: `6`
- conflict found: `false`

So the direct valid-DER lift of the toy gadget is already dead:

**the obvious toy conflict pattern does not survive the move into exact-15 DER.**

## Result 4: this narrows the DER path again

The cumulative picture is now:

- overlap alone is not enough;
- conflict seems necessary in every expressive family we have found;
- overlap-bearing exact-`13` DER stayed conflict-free and subset-like;
- the first direct valid-DER lift of the toy conflict gadget also stays
  conflict-free and subset-like.

That is a meaningful shift.

The repo should no longer think of the open problem as:

> maybe a slightly longer DER with the right motif will finally show conflict

It should now think:

> if conflict-bearing valid DER exists at all, it probably needs a more radical construction than a single embedded anchor plus a short repeated code

## What is left

The next worthwhile moves are:

1. search for **multi-anchor** or repeated-body DER families that can create
   pre-existing false token instances more aggressively;
2. search a different valid selectable blob family entirely, rather than trying
   to stretch single-anchor DER further;
3. if those also fail, treat `FindAndDelete`-based valid-blob search as close
   to exhausted and move the repo toward a different verification surface.

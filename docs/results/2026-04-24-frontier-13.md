# Frontier-13

Date: 2026-04-24

This report follows `frontier-12`.

`frontier-12` showed that even **double-anchor DER** stays completely flat.

That left the next obvious mechanism-aware DER question:

> what if the payload plants the pushed-token anchor three times instead of two?

The new tool for this step is `tools/der_triple_anchor_frontier.py`.

It studies **triple-anchor DER** families:

- exact-length DER payloads,
- one-byte `r`,
- `s` begins with the exact pushed-token anchor for that same length,
- and then embeds that same anchor two more times inside the body.

This is the strongest DER-shaped gadget in the repo so far. It is no longer a
short motif search. It is a direct attempt to manufacture multiple pre-existing
anchor instances inside one valid token.

## Result 3: this is now the strongest DER exhaustion point in the repo

The DER story has become much tighter across the last steps:

- overlap-bearing exact-`13` DER exists, but stays conflict-free and subset-like;
- the single-anchor conflict-gadget lift fails;
- double-anchor DER stays flat;
- and now triple-anchor DER stays flat too.

That means the negative result is no longer “random DER looks bad.”

It is now:

**the repo has tried increasingly mechanism-aware valid-DER constructions with one, two, and three planted anchors, and they all still collapse to plain subset behavior.**

At this point, plain DER-shaped selectable blobs look very close to exhausted.

## Result 4: what the repo should do next

The next serious step should no longer be “one more DER anchor variant.”

The realistic options are now:

1. **repeated-body plus anchors**
   move beyond planted anchors alone and deliberately engineer repeated bodies
   around them;
2. **different valid selectable blob family**
   stop insisting on DER-shaped blobs and test a different class of valid pushed
   tokens entirely;
3. **leave valid-blob `FindAndDelete` search behind**
   if the first non-DER family also fails, move the repo toward a different
   verification surface.

Based on the current evidence, the second option now looks like the highest-ROI
next step.

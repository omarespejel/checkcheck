# Frontier-19

Date: 2026-04-24

This report follows `frontier-18`.

`frontier-18` tested the conservative stack-correct polyglot selection gadget:

- use `OP_PICK` to copy the selected polyglot element for the HORS check;
- then use a second pool `OP_ROLL` to move the same element into the
  `CHECKMULTISIG` signature zone.

That was stack-correct but too expensive.

This step runs the final rescue search requested by the project:

> can we avoid `OP_PICK + OP_ROLL` and recover the asymmetric polyglot frontier?

The answer is **yes**.

## Result 1: cheaper stack gadget found

The working signed-selection gadget is:

```text
roll index from witness
sanitize with OP_MIN
add pool offset
OP_ROLL selected polyglot element
OP_DUP selected element
roll HORS preimage
OP_HASH160
OP_EQUALVERIFY
```

Why it works:

- the selected hardcoded element is already both the HORS commitment and the
  dummy signature;
- after `OP_ROLL`, the script does not need the index anymore;
- `OP_DUP` creates two copies of the selected polyglot element;
- one copy is consumed by `HASH160(preimage) == element`;
- the other copy remains on top as the signature for `CHECKMULTISIG`.

So the gadget avoids both expensive operations from `frontier-18`:

- no `OP_PICK`;
- no second pool `OP_ROLL`.

## Go/no-go

Decision:

**GO for continuing the polyglot branch.**

Not because the construction is production-ready. It is not.

But because the specific thing that could have killed it did not kill it:

- the cheaper stack gadget exists;
- it avoids `OP_PICK + OP_ROLL`;
- it validates over different index paths;
- it restores the `143` threshold;
- and it restores a baseline-collision crossing under current script limits.

The next gate is now more concrete:

1. turn this symbolic round into a transaction-level script builder;
2. run it through a real Bitcoin Script interpreter or regtest spend;
3. only then decide whether to pitch it externally.

## Bottom line

This branch is alive again.

The repo now has a clear positive result:

**a stack-correct polyglot selection gadget recovers almost all of the
asymmetric frontier without `OP_PICK + OP_ROLL`.**
